# 分节计划

## 用途

把一个大主题拆成若干可独立阅读、可独立验收的章节，并为每个章节写清楚：要覆盖哪些知识点、依赖哪些前置知识、引用哪些来源、写到什么程度算完成。

**开始时声明：**"我先用分节计划技能把这个主题拆开，再动笔。"

计划本身是一份笔记草稿，用 `note_create` 保存，标题形如 `《<主题>》分节计划`。

## 先判断要不要拆

不是所有内容都需要计划。**单个章节能讲完的主题直接写，不要为它造计划。**

需要分节计划的信号：主题横跨多个彼此独立的子领域；来源材料超过三份；用户明确要求"系统""全面""从零开始"；预期成稿超过三千字。

如果主题横跨多个互不依赖的领域，建议拆成多篇笔记，每篇独立成文——而不是一篇里塞四个平行主题。

## 章节的合适粒度

一个章节是**读者可以单独读完并有收获的最小单元**。判断边界的方法：如果一个读者可能只读这一节就走，它是否自成一体？如果两节必须连着读才有意义，合并它们。

把定义、背景、示例、常见误区折叠进它们服务的那个知识点里，不要单独成节。只有当两部分内容可以被独立评价对错时，才拆开。

## 计划文档的头部

每份计划都以这段开头：

```markdown
# 《[主题]》分节计划

**目标读者：** [他们已经知道什么，缺什么]
**成稿目标：** [一句话说明读完能做到什么]
**来源材料：** [逐条列出，标明每条覆盖哪部分]

## 全局约束
[术语的统一译法、记号约定、要不要配图、篇幅上限——每条一行，后面每节都默认遵守]

---
```

## 章节结构

每个章节写成这样：

````markdown
### 第 N 节：[章节标题]

**覆盖的知识点：**
- [知识点一，用一句陈述句写出结论，不要写"介绍 X"]
- [知识点二]

**前置依赖：** [读者需要先读第几节，或需要什么外部背景]
**后续被依赖：** [哪几节会用到本节的结论，以及用到的是哪个具体概念]

**来源支撑：**
- [来源名称] → 用于支撑哪个知识点

**必须包含：**
- [ ] 一个具体例子（写出例子本身，不要写"举个例子"）
- [ ] 一张对比表 / 一个 mermaid 图（写出它要对比什么）
- [ ] 常见误区（写出误区的具体内容）

**验收标准：** [读完这节，读者应该能回答的一个具体问题]
````

## 不许留占位符

计划里的每一条都必须是可以直接照着写的内容。下面这些是**计划失败**，不是待办：

- "待补充""稍后展开""这里详细讲讲"
- "介绍相关概念""说明其重要性"——没说要介绍哪个概念、重要在哪
- "举例说明"——不写出例子是什么
- "同第 N 节"——重复写一遍，读者可能跳着看
- 引用了某个前面没定义过的术语

## 写完自查

写完整份计划后，用新的眼光对照来源材料检查一遍。这是你自己跑的清单，不是派给别人的活。

**一、覆盖度：** 逐条过来源材料，每条内容都能指到某一节吗？列出缺口。

**二、占位符扫描：** 按上一节的清单搜一遍自己的计划，改掉。

**三、术语一致性：** 后面章节用的术语，和前面定义的是同一个词吗？第 3 节叫"上下文窗口"、第 7 节叫"context 长度"就是 bug。

**四、依赖成环：** 有没有两节互为前置？有就合并或者重新切。

发现问题当场改，不用再审一遍。发现某条来源材料没有对应章节，补一节。

## 交接

计划保存后，问用户：

**"分节计划已保存。接下来两种推进方式：**

**一、逐节撰写**——我按顺序一节一节写，每节写完你可以先看再继续。

**二、并行撰写**——彼此不依赖的章节同时展开，最后统一审校。适合章节多且依赖少的情况。

**选哪种？"**

选逐节就用 `executing-plans` 技能；选并行就用 `dispatching-parallel-agents` 技能。
