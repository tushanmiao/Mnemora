# 并行分派

## 用途

把彼此独立的子任务分给各自的执行者，每个执行者只拿到自己需要的上下文。你负责精确构造他们的指令，他们不继承你这一轮的对话历史——这既让他们专注，也保住了你自己的上下文余量。

**核心原则：** 每个独立的问题域派一个执行者，让他们并发推进。

## 什么时候用

**适合：**

- 分节计划里有三节以上，彼此没有前置依赖
- 要同时调研多份来源材料，每份可以独立读懂
- 要分别核查几个不相干的说法
- 子任务之间不需要共享中间结论

**不适合：**

- 章节之间有依赖（第 3 节要用第 2 节的结论）
- 需要通盘理解全部材料才能下笔
- 还在探索阶段，连要分几块都没想清楚
- 多个执行者会写同一篇笔记（会互相覆盖）

## 做法

### 一、划分独立域

按"缺了另一块也能讲清楚"来分组。比如一份讲某个框架的笔记：

- 第 2 节：核心概念——不依赖任何其他节
- 第 4 节：生态与周边工具——不依赖第 2 节
- 第 5 节：与同类方案对比——不依赖前两节

这三节可以并行。而"第 6 节：最佳实践"要用到前面全部结论，必须等它们写完。

### 二、构造聚焦的任务

每个执行者要拿到：

- **明确范围：** 只写哪一节，或只读哪一份材料
- **明确目标：** 这一节要覆盖哪些知识点（从分节计划里原样抄过来）
- **约束：** 不要涉及别节的主题；术语按全局约束里的译法
- **产出格式：** 返回什么——正文本身，还是摘要加要点

### 三、同时分派

把所有分派放在同一次回复里发出，它们才会并发执行。一次回复一个 = 串行。

### 四、汇总与整合

执行者返回后：

- 逐份读他们的产出
- 检查是否有重复论述（两节都花篇幅解释了同一个概念）
- 检查术语是否一致
- 检查有没有互相矛盾的说法——这是并行最容易出的问题
- 按计划顺序合并进成稿

## 任务提示词的写法

好的任务提示词有三个特征：**范围单一、自身完备（不需要看别的上下文就能理解）、明确说清要返回什么。**

```markdown
撰写《[主题]》的第 4 节：[章节标题]

要覆盖的知识点（不要增删）：
1. [知识点一]
2. [知识点二]

前置背景（读者已在前面章节读到，本节可直接引用，不要重复解释）：
- [概念 A 的定义]

来源材料：用 knowledge_search 检索 "[检索词]"，以原文为准，不要凭记忆复述。

必须包含：一个具体例子、一张对比表。
术语约定：[统一译法]

不要写引言和总结段，只写本节正文——它会被合并进整篇笔记。

返回：本节的完整 markdown 正文。
```

## 常见错误

**范围太宽：** "把这篇笔记写了" —— 执行者会跑偏
**要聚焦：** "写第 4 节，覆盖这两个知识点"

**没给背景：** "讲讲它的优势" —— 执行者不知道跟什么比
**要给背景：** 把前置概念的定义贴进去

**没给约束：** 执行者会自作主张加引言、加总结、重新定义术语
**要给约束：** "不要写引言和总结""术语按这个译法"

**产出格式含糊：** "写一下" —— 你不知道拿回来的是正文还是大纲
**要明确：** "返回本节的完整 markdown 正文"

## 什么时候别用

**章节有依赖：** 先写完前置的，再并行后面的
**需要通盘视角：** 比如"全书术语表"这种必须看完全部内容才能写
**探索阶段：** 还没想清楚分几块的时候，先自己理一遍
**会互相覆盖：** 多个执行者写同一篇笔记的同一处

## 汇总时必查

1. **逐份读产出** —— 不要只看执行者的自述摘要
2. **查重复** —— 有没有两节讲了同一件事
3. **查矛盾** —— 并行产出最容易在细节上打架
4. **查术语** —— 同一个概念有没有出现两种译法
5. **抽查事实** —— 执行者可能犯系统性错误，抽几条核对来源
