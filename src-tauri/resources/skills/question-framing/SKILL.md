# 问题框定

先确保正在解决的是正确的问题，再开始给方案、做研究或执行任务。目标不是制造更多抽象层级，而是揭示真正影响结论的因果关系、假设和边界。

## 工作流程

1. 用一句话复述用户表面上在问什么，并找出背后那个没有明说、但更可能决定结果的问题。
2. 判断本轮的主要目标：理解机制、描述现状、比较方案、寻找原因、预测结果，还是设计解决方案。不要把不同类型的问题混成一个答案。
3. 固定含糊词的含义。对“更好”“更快”“支持”“智能”“稳定”等词，说明它们在本问题中具体由什么现象或指标代表。
4. 写出因果链：哪些输入、条件或机制会造成哪些中间变化，最终如何影响用户关心的结果。证据不足时标为假设，不把相关性写成因果。
5. 检查可回答性：现有对话、附件和工具能够证明什么；还缺什么；缺失信息是否真的会改变答案。能自行查证的事实不要反问用户。
6. 标出两到四个承重假设，并说明每个假设若不成立，会如何改变结论或方案。
7. 收敛范围：区分本轮必须回答、可顺带解释和暂时不处理的内容，避免被有趣但无关的分支带走。
8. 给出框定后的核心问题，再进入分析或交给合适的后续 Skill。简单问题可在内部快速完成，不必机械展示整套表格。

## 输出要求

- 先回答用户真正需要知道的结论，不要让“问题框定”本身抢占正文。
- 若发现用户没问但更关键的问题，应明确指出它为什么更关键。
- 面向零基础用户时，先用日常语言说明核心机制；首次出现关键技术概念时保留英文原名并解释中文含义。
- 清楚区分：已知事实、基于事实的推断、待验证假设和个人建议。
- 只有缺失信息会导致截然不同的行动时才提问；每次尽量只问一个最关键的问题，并给出推荐倾向。
- 不要为了显得深入而堆砌层级、术语、矩阵或空洞框架。

## 完成标准

最终应能用一小段话说清楚：真正的问题是什么、为什么重要、哪些机制决定答案、当前能确认什么、还存在哪个关键未知项，以及下一步应分析或执行什么。
