# 按计划撰写

## 用途

读取分节计划，先带着批判眼光过一遍，然后逐节撰写，每节结束时汇报进度。

**开始时声明：**"我按分节计划逐节撰写。"

**提示：** 如果章节之间依赖很少、数量又多，`dispatching-parallel-agents` 技能会更快。本技能适合章节之间有明确先后依赖的情况。

## 流程

### 第一步：读取并审视计划

1. 用 `note_read` 读取计划笔记
2. 带着批判眼光过一遍——哪些地方你觉得写不下去、或者觉得计划本身有问题
3. 有疑虑：先跟用户提出来，不要闷头开写
4. 没疑虑：把每一节登记成待办，开始推进

### 第二步：逐节撰写

对每一节：

1. 标记为进行中
2. 严格按计划里列的知识点写——计划说要有一个具体例子，就写出那个例子；说要有对比表，就写出表
3. 需要引用来源时，用 `knowledge_search` / `knowledge_read` 取回原文，或用 `web_fetch` 取回网页，**不要凭记忆复述来源内容**
4. 写完对照本节的"验收标准"自查：读者读完真的能回答那个问题吗
5. 用 `note_update` 追加到成稿笔记，标记本节完成

### 第三步：收尾

全部章节写完后：

- 通读一遍，检查术语是否前后一致、有没有重复论述
- 检查计划里标注的依赖关系在成稿里是否真的成立（第 5 节说依赖第 2 节的结论，第 2 节真的给出那个结论了吗）
- 用 `verification-before-completion` 技能做最后的证据自查，再向用户汇报完成

## 什么时候停下来问

**立刻停止并求助的情况：**

- 计划里某节要求引用的来源找不到、或者内容对不上
- 某节的知识点你没有可靠依据，只能靠猜
- 计划有关键缺口，导致这一节没法开写
- 看不懂计划里某条要求的意思

**宁可问清楚，也不要猜着写。**知识笔记里编造的内容比空缺更有害。

## 什么时候回到第一步

- 用户根据你的反馈改了计划
- 撰写过程中发现整体切分方式不对

**不要硬顶着障碍往下写**——停下来说明情况。

## 要点

- 先批判性地过一遍计划
- 严格按计划里的知识点写，不自行增删主题
- 引用来源必须实际取回原文，不凭记忆
- 每节都对照验收标准自查
- 卡住就停，不要猜
