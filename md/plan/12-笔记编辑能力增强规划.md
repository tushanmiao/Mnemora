# Plan 12：Mnemora 笔记编辑能力增强规划

> 基线：Mnemora eb3abfe / 0.1.16，2026-08-22。  
> 目标：把“能改 Markdown”提升为可靠、可回退、来源感知、对图形和公式友好的知识编辑器。

## 1. 问题定义：缺的不是按钮，而是编辑内核

当前 NoteWorkspace/NoteEditor 已有 Markdown 源码、预览、标题、自动保存、分组、搜索、排序、大纲、选区引用、笔记 Chat、选区 AI 修改、PDF 来源和版本备份基础；源码编辑仍主要是 textarea，用户因此会遇到：

- 大文档输入、选区、跳转和结构操作不稳定；
- Mermaid、KaTeX、代码块和来源标记容易被普通文本替换破坏；
- AI 修改难以判断改了什么、依据什么、是否覆盖了手工编辑；
- 版本、并发保存、离线草稿和冲突恢复缺少清晰的用户模型。

真正的目标链路是：

~~~text
稳定文本编辑内核
→ 可发现的结构化操作
→ Markdown AST 定位
→ 版本/Undo/冲突处理
→ 来源、Mermaid、公式和代码保护
→ AI Proposal / Diff / 确认 / 原子应用
~~~

## 2. 推荐决策

采用 Source-first + Preview-first：

1. Markdown 源码是权威数据；
2. Preview 沿用 Chat 的安全 Markdown、Mermaid 和 KaTeX 渲染；
3. 第一阶段引入 CodeMirror 6 级文本编辑内核，而不是直接换成重量级 WYSIWYG；
4. 用命令系统提供标题、列表、表格、代码、Mermaid、公式和链接操作；
5. AI 编辑永远是 Proposal → Diff → 影响/来源预览 → 用户确认 → 原子应用；
6. Markdown AST 只用于导航、诊断和最小 Patch，不把全文转换成另一种不可逆格式；
7. 第二阶段再对 Milkdown、Tiptap/ProseMirror 做小范围 PoC。

Source Editor、Preview 和 AI Proposal 不应分别维护三份“真相”；它们都引用同一 revision/hash。

## 5. 编辑模式和交互

### 5.1 Source / Preview / Split

- Source：专业用户的完整 Markdown 编辑；
- Preview：只读安全渲染，支持复制、选区引用和跳回源位置；
- Split：左右或上下同步，滚动映射按 AST 节点/块，而不是按字符比例；
- 小屏或内存压力时自动退回 Source-only，避免同时保留两套大型 DOM。

### 5.2 结构命令

第一阶段命令：

- 标题级别升降、章节移动、折叠；
- 无序/有序/任务列表、引用、表格；
- 插入代码块并选择语言；
- 插入 Mermaid 模板（flowchart、sequence、state、mindmap）；
- 插入行内/独立公式模板；
- 链接、图片和来源引用；
- 查找、替换、跳转标题、跳转 Mermaid/公式/代码块；
- 命令面板、快捷键和可访问性标签。

命令必须基于当前 selection 和 AST Range 生成最小文本事务；不能用正则重写全文。

## 6. Markdown AST 与特殊块保护

建议管线：

~~~text
Markdown Parser
→ Node/Range 定位
→ 最小文本 Patch
→ 保留未涉及文本
→ Validator
→ Preview
~~~

必须保护：

- Mermaid 顶层代码块及其围栏；
- $...$ 和 $$...$$ 数学节点；
- 普通代码块及语言标签；
- Evidence、source ID、页码和行号；
- 图片路径、Alt 文本和安全 HTML；
- 用户未选中的章节。

规则：

1. 用户未明确选择时，AI 和结构命令不能进入代码、Mermaid、公式块；
2. Mermaid 修复必须先做语法诊断，再生成局部替换；
3. 公式修复只允许 KaTeX 兼容的数学节点，不生成 latex/math 普通代码块；
4. 来源标记若因删除正文而失效，应显示断链诊断，不静默删除证据。

### 7.2 操作流程

~~~mermaid
sequenceDiagram
    participant U as 用户
    participant E as 编辑器
    participant A as AI
    participant S as Store
    U->>E: 选择范围并提出要求
    E->>A: 发送选区、章节、来源和 baseHash
    A-->>E: Proposal + Diff + 来源 + 风险
    E-->>U: 预览变更
    U->>S: 确认或拒绝
    S->>S: 校验 baseHash
    S->>S: 版本备份与原子应用
    S-->>E: 新 revision
~~~

禁止 AI 直接覆盖整篇笔记。补丁必须声明范围、旧 Hash、动作、来源和影响等级；过期 Proposal 必须重新生成。

## 8. 版本、撤销和冲突

建议扩展 library_note_versions：

~~~text
id
noteId
parentVersionId
title
content
contentHash
reason
sourceRunId
createdAt
~~~

用户能力：

- 普通 Undo/Redo：编辑器内存级，限制历史字节；
- 保存版本：事务级，可命名；
- Diff：按 Markdown block 显示，不只按字符；
- 恢复：恢复前创建当前版本备份；
- 冲突：使用 expectedUpdatedAt/baseRevisionHash 检测，不静默覆盖；
- 合并：本地、服务端、手工三方选择；无法自动合并时保留双方文本。

## 9. 自动保存和离线

输入先写内存草稿，debounce 后携带 expectedUpdatedAt 保存。保存队列需要：

- generation 号，旧保存完成后不能覆盖新输入；
- 失败重试和离线标记；
- 关闭/切换时 flush 或明确提示；
- 崩溃恢复草稿；
- 只在服务端确认成功后更新 lastPersistedHash。

保存成功、失败、冲突、恢复都应写事件，方便任务中心和重新进入页面时恢复最后状态。

## 10. 性能、可访问性和安全

- 单笔记编辑器单实例挂载；
- 预览使用 deferred content，Mermaid/KaTeX 按可见区域延迟加载；
- 大纲和诊断增量化；
- Undo 历史和版本正文设置字节上限，超过后压缩或差异存储；
- 500 KB 以上显示性能提示，2 MB 以上默认 Source-only；
- 键盘可达、焦点可见、屏幕阅读器能读出模式和脏状态；
- 尊重 Reduced Motion；
- 预览继续使用现有 HTML/Mermaid 净化，不执行脚本、外链或 click；
- 粘贴 HTML 时转为安全 Markdown/纯文本，不能把任意事件属性带入预览。

## 11. 分阶段路线和难度

| 阶段 | 工作 | 难度 |
| --- | --- | --- |
| P12.1 | CodeMirror、Undo/Redo、保存状态、查找、冲突检测 | 中 |
| P12.2 | Markdown 命令、AST 导航、诊断、Source/Preview/Split | 中高 |
| P12.3 | 版本 Diff、恢复、离线草稿、三方冲突 | 高 |
| P12.4 | AI Proposal、来源/影响预览、局部 Patch | 高 |
| P12.5 | Mermaid/公式专用修复器、块移动、性能优化 | 高 |
| P12.6 | WYSIWYG/协同编辑 | 很高，不建议近期做 |

优先顺序是可靠编辑内核、版本和冲突，然后才是 WYSIWYG。若先做块编辑，后续会同时承担 Markdown 往返、来源迁移和历史数据迁移三项高风险工作。

## 12. 测试与验收

### 测试矩阵

- 纯文本、中文、混合 Markdown、超长代码块；
- 嵌套/错误 Mermaid、KaTeX、表格、图片和来源标记；
- 断网、保存失败、应用崩溃、重复点击和并发修改；
- AI Proposal 过期、空补丁、越界补丁、来源不匹配；
- 500 KB/2 MB 笔记的输入延迟、内存和滚动；
- 键盘导航、Reduced Motion、缩放和高 DPI。

### 验收标准

1. 断网不丢草稿，重启可恢复；
2. 并发修改不静默覆盖；
3. Mermaid、公式和代码仍能安全渲染；
4. AI 修改必须确认并可一键拒绝；
5. 版本可查看、Diff、恢复；
6. 选区 Chat 使用正确 revision Hash；
7. 来源未被篡改或伪造；
8. 大笔记在目标设备上仍可编辑；
9. 所有失败路径可从 SQLite/事件重建，而不是只依赖 React 状态。

> 第一阶段目标不是复制 Notion，而是把当前 Markdown 编辑器升级为可靠、可回退、来源感知的知识编辑器。
