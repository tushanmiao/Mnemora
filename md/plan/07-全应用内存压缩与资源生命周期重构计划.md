# Mnemora Plan 07：全应用内存压缩与资源生命周期重构

> 用途：在不牺牲流畅性、稳定性、可用性和数据完整性的前提下，持续降低 Mnemora 的 Windows/WebView2 内存占用，并建立可以长期执行的测量、回归和重构体系。
>
> 状态：设计决策已于 2026-08-06 完成逐项确认，实施尚未开始。当前源码参考提交为 `a93a0ca`，工作区包含 Plan06 的未提交实现，执行 Plan07 时必须保留并与其协同。
>
> 一句话目标：把内存从“任务管理器里看到一个无法解释的 500 MB+ WebView2”变成“每个场景都有预算、每类资源都有所有者、离场后能够回收、性能回归会被自动阻止”的可治理系统。

---

## 一、真正要解决的问题

当前问题不只是某个变量、缓存或组件泄漏，而是 Mnemora 尚未建立完整的资源治理合同：

1. 没有 Release 冷启动基线，调试模式、Vite/HMR、React 开发构建和产品真实占用混在一起。
2. 任务管理器只能看到进程结果，无法区分 JS Heap、DOM、Canvas、GPU、ArrayBuffer、Worker 和 WebView2 基础成本。
3. 页面卸载不等于模块、图形资源和浏览器分配器立即归还内存。
4. PDF、Mermaid、附件预览、音频、长对话和 Agent Workflow 都可能随使用历史累积资源。
5. 现有局部上限彼此独立，缺少全应用统一预算和内存压力响应策略。
6. 如果没有自动基准，单次优化即使有效，也会在后续功能迭代中悄然回归。

因此 Plan07 不是“清理几个 `useEffect`”或“手动调用 GC”，而是同时建立：

- 可信的 Release/Development 双基线；
- 场景化内存与流畅性双门禁；
- 状态可恢复、运行资源可销毁的生命周期；
- PDF、Chat/Agent、Markdown、附件和音频的明确资源预算；
- Rust 持有长期状态、WebView 只持有有限投影的职责边界；
- 由证据触发的 Worker/独立 WebView 隔离；
- 仅开发构建可用的本地真实数据诊断工具。

## 二、已确认的不可变原则

以下决策属于 Plan07 的产品基线，实施时不得自行放宽：

1. **Release 是产品验收基线**：开发模式只监控回归趋势，不与 Release 共用同一个绝对阈值。
2. **预算不是优化终点**：首次达到 `220/280/380 MB` 后仍继续降低，前提是流畅性、稳定性和可用性不退化。
3. **状态可恢复，资源可丢弃**：页码、缩放、学习进度、会话和 Workflow 必须保留；Canvas、Worker、音频对象、图表 DOM 和临时缓存可以重建。
4. **不得用卡顿换内存**：频繁 GC、同步序列化、滚动时清理、闪烁重载和高频资源抖动均不可接受。
5. **不得自动重载窗口**：超过预算时只能执行无损降级，不得通过刷新 WebView、打断任务或丢弃数据解决。
6. **PDF 使用自适应质量**：当前页优先清晰，相邻页可以降低临时分辨率，全局 Canvas 初始预算为 `64 MB`。
7. **完整历史仍然存在**：原始 reasoning、Tool、Skill、审批和 Workflow 完整保存并可查看；分页只改变前端常驻范围，不删除内容。
8. **Rust 是 Agent 运行真相来源**：切换页面不终止 Agent；前端可以释放 Workflow DOM 和历史窗口，再从后端事件恢复。
9. **隔离必须由数据触发**：常规清理后仍稳定残留超过约 `30 MB`，才考虑临时 Worker 或独立 WebView。
10. **分阶段交付**：每个阶段都要重新测量；无法证明收益的复杂重构不得继续扩张。
11. **最小化轻量休眠**：空闲约 60 秒后暂停非必要渲染和预取；最小化不自动销毁整个 WebView。
12. **关闭到托盘销毁 WebView**：沿用当前窗口策略，释放 WebView2 进程组；当前未完成运行和审批按已确认策略取消。
13. **内存与性能双门禁**：任一门禁失败，变更不能合并。
14. **真实数据只用于开发诊断**：使用本地只读快照，禁止修改真实会话、学习进度、阅读状态和设置。
15. **正式版编译期排除高级诊断**：不是隐藏按钮，而是不打包真实数据基准、调试端口和强制资源操作。
16. **Windows + WebView2 优先**：本计划只对 Windows 强制验收，代码边界保持未来可移植。
17. **重构必须与目标相关**：只纳入能够改善内存、性能、生命周期或可测试性的改造。

### 2.1 明确非目标

- 不在 Plan07 中重新设计 UI 视觉风格。
- 不替换 React、Tauri 或 WebView2 框架。
- 不删除 reasoning、工具轨迹或历史消息来伪造低内存。
- 不通过降低模型能力、Agent 上限或修改用户模型来降低占用。
- 不将手动“清理内存”按钮当成正常生命周期的替代品。
- 不承诺仅凭任务管理器的一次截图定位根因。
- 不在没有测量证据时预先拆出多个 WebView。

## 三、当前运行事实

### 3.1 进程树采样

2026-08-05 对当前调试实例进行归属到 Mnemora 根 PID 的精确采样，结果如下：

| 进程类型 | Working Set | Private Bytes |
| --- | ---: | ---: |
| WebView Renderer | 549.7 MB | 488.3 MB |
| WebView Browser | 132.5 MB | 45.2 MB |
| WebView GPU | 100.3 MB | 112.7 MB |
| Mnemora Rust | 88.6 MB | 31.0 MB |
| Network Service | 39.6 MB | 13.5 MB |
| Audio Service | 24.1 MB | 9.2 MB |
| Storage Service | 20.9 MB | 9.1 MB |
| Crashpad | 11.1 MB | 2.7 MB |
| **合计** | **966.8 MB** | **711.7 MB** |

Renderer Private Bytes 峰值曾达到约 `684.9 MB`，回落后仍稳定在约 `488.5 MB`。三次采样没有出现明显瞬时抖动。

### 3.2 必须正确解释的数据

- 当前命令是 `cargo run`，使用 `target/debug/mnemora.exe` 和 Vite 开发服务器，不是 Release 包。
- 当前 WebView2 Runtime 为 Edge/WebView2 151 系列。
- 系统中存在其他 WebView2 应用，不能汇总全部 `msedgewebview2.exe`，必须沿 Mnemora PID 树采样。
- Rust Private Bytes 约 `31 MB`，当前首要异常集中在 Renderer，而不是 Rust 后端。
- Audio Service Private Bytes 约 `9.2 MB`，说明音频能力被使用过，但它不是 488 MB Renderer 的主要解释。
- 当前唯一会话文件只有约 `531 B`，本次高占用不是大量会话正文直接造成。
- WebView2 Code Cache 在磁盘约 `65.8 MB`、3185 个条目，这是历史开发缓存，不应直接等同于当前进程内存。
- `dist/assets` 曾积累约 153 MB、2965 个文件，属于构建产物卫生问题，不是当前 Vite 调试 Renderer 的直接根因，但必须防止进入正式包。

### 3.3 当前已有的正确基础

- `WorkspaceViewHost` 同一时间只渲染一个工作区，切换后会卸载旧视图。
- PDF 阅读器离场时调用 `loadingTask.destroy()`，页面离开活跃范围时会清空 Canvas 和文本层。
- PDF 加载已关闭自动全文预取，使用 256 KB Range 读取。
- Chat 消息列表已经使用 `virtua` 虚拟化 DOM。
- Mermaid、KaTeX、Highlight.js、PDF Reader 和部分工作区已使用动态加载。
- 音频组件会 `pause()`、移除 `src` 并调用 `load()`。
- 附件预览和会话缓存已有数量/文本字节上限。
- 关闭主窗口时会销毁 WebView，只保留 Rust 后端与托盘。

这些基础说明 Plan07 应优先补齐预算和所有权，而不是推倒重来。

### 3.4 已发现的差距

| 模块 | 当前行为 | 风险 |
| --- | --- | --- |
| PDF 页面 | 为全部页创建 React 组件和 IntersectionObserver | 超长 PDF 即使不渲染 Canvas，也会积累组件、Observer 和 DOM 壳 |
| PDF Canvas | 单页最高 1200 万像素，约 45.8 MB RGBA | 相邻多页同时活跃时可迅速超过 100 MB |
| PDF 预加载 | 页面 `rootMargin=600px`，缩略图 `500px` | 高 DPI、大窗口或快速滚动时并发资源过多 |
| PDF 缩略图 | 为全部页创建按钮和 Observer | 1000 页级文档会产生大量节点和观察器 |
| PDF 搜索 | 顺序读取所有页文本 | 搜索期间产生大量临时文本、PageProxy 和主线程工作 |
| Chat 数据 | DOM 虚拟化，但完整 Conversation 仍在 React 状态 | 长消息、reasoning 和 Workflow 仍常驻 JS Heap |
| 会话缓存估算 | 只覆盖主要文本，遗漏 ToolTrace、Workflow 等结构成本 | 8 MB 逻辑预算不等于真实堆预算 |
| 保存链 | Promise 链可能暂时持有旧 Conversation 快照 | 流式运行和频繁保存时扩大短期峰值 |
| 附件预览 | Rust 返回 Data URL，前端缓存 8 MB UTF-16 字符串 | Base64、字符串、解码位图和 DOM 可能同时存在多份副本 |
| Mermaid | 动态加载后模块无法从当前页面模块表单独卸载 | 首次使用后的模块和图形运行时可能常驻 |
| Markdown | 虚拟列表能卸载 DOM，但消息对象和派生结果仍可能保留 | 长对话中的解析、outline、SVG、highlight HTML 需要按可见性释放 |
| 设置页 | 部分设置面板仍为静态导入 | 默认 Chat 启动时加载不必要模块 |
| 诊断 | 没有统一采样、场景标签和自动回归 | 无法判断优化收益来自哪里，也无法阻止回归 |

## 四、测量模型

### 4.1 三层指标

Plan07 不使用单一“内存 MB”判断结果，而是同时记录：

1. **用户观察层**
   - 任务管理器中 Mnemora/WebView2 分组显示值；
   - 冷启动、普通使用和重型场景峰值；
   - 离开重型场景后的肉眼回落。

2. **进程层**
   - Mnemora 根进程和全部子进程的 Working Set、Private Bytes、峰值；
   - Renderer、GPU、Browser、Network、Audio、Storage 分项；
   - 进程创建/销毁时间和 WebView2 Runtime 版本。

3. **页面资源层**
   - JS Heap used/total、ArrayBuffer/external memory；
   - DOM Node、EventListener、Mutation/Resize/IntersectionObserver 数量；
   - Canvas 数量、宽高、总像素、估算 RGBA 字节；
   - Worker、Audio、Object URL、Data URL 和活动计时器数量；
   - Conversation、Message、Workflow Event 和缓存条目数量。

### 4.2 核心计算

```text
scene_delta = active_peak - baseline_before_scene
residual = post_exit_60s - baseline_before_scene
return_ratio = (active_peak - post_exit_60s) / scene_delta
cycle_slope = (cycle_N_post_exit - cycle_1_post_exit) / (N - 1)
```

临时判定：

- 重型场景离开 60 秒后 `residual <= 30 MB`；
- `return_ratio >= 80%`；
- 10 次进入/退出的 `cycle_slope <= 2 MB/次`；
- 任何连续阶梯增长都必须定位，不能用“浏览器会缓存”直接关闭问题。

### 4.3 冷、暖、污染实例

- **Cold Release**：新进程、无 DevTools、无 HMR，正式验收依据。
- **Warm Release**：同一进程已使用过目标功能，用于验证离场回收和重复进入。
- **Cold Development**：新调试进程，用于开发趋势对比。
- **HMR-soaked Development**：长时间编辑后的调试进程，只用于发现开发体验问题，不作为产品预算。
- **Real-data Snapshot**：开发诊断构建读取真实数据只读副本，用于规模压力测试。

### 4.4 采样规则

- 每个场景至少运行 3 次，记录中位数、P95 和峰值。
- 场景切换前稳定 30 秒；离场后分别在 5、15、30、60 秒采样。
- 正式验收不依赖强制 GC；可额外执行一次诊断 GC，用于区分可达对象与分配器保留。
- 测试期间记录窗口大小、DPI、系统 RAM、WebView2 版本和是否使用硬件加速。
- 禁止在用户正在工作的 Mnemora 窗口上自动执行场景切换。

## 五、预算阶梯

### 5.1 第一阶段强制门槛

以下是首轮 Release 基线后的临时产品目标：

| 场景 | 临时目标 |
| --- | ---: |
| 空闲 Release | `<= 220 MB` |
| 普通 Chat | `<= 280 MB` |
| 单个 PDF 活跃 | `<= 380 MB` |
| 离开 PDF/English 后 | 场景基线 `+30 MB` 内 |

这些值必须同时标注测量口径。若 WebView2 版本的不可控基础成本使某个 Working Set 指标无法达到，只能提交完整分项证据并重新确认，不能静默放宽。

### 5.2 持续下降目标

第一阶段达标后，继续尝试以下 Stretch 目标：

| 场景 | Stretch A | Stretch B |
| --- | ---: | ---: |
| 空闲 Release | `<= 190 MB` | `<= 170 MB` |
| 普通 Chat | `<= 240 MB` | `<= 220 MB` |
| 单个 PDF 活跃 | `<= 330 MB` | `<= 300 MB` |

Stretch 目标不是通过降低功能、清晰度或流畅性强行实现。每次降低预算后必须重新运行完整性能和功能矩阵。

### 5.3 性能双门禁

| 指标 | 临时门槛 |
| --- | ---: |
| Release 冷启动到可交互 | `<= 1.5 s`，且相对基线退化 `<= 5%` |
| 普通交互响应 P95 | `<= 100 ms` |
| 轻量工作区切换 P95 | `<= 150 ms` |
| PDF/English 主要内容恢复 P95 | `<= 800 ms` |
| 主线程长任务 | 不允许因内存清理产生持续 `>50 ms` 长任务 |
| Chat 滚动/流式输出 | 无持续掉帧、跳动或输入阻塞 |

## 六、目标架构

```text
Windows process sampler
        |
        v
Memory Diagnostics Coordinator  <---- Scenario/CI benchmark runner
        |
        +---- Resource Budget Manager
        |       +---- Canvas budget
        |       +---- Preview/cache budget
        |       +---- Message window budget
        |       +---- Worker/audio/object URL registry
        |
        +---- Workspace Lifecycle
        |       +---- active
        |       +---- background/minimized
        |       +---- disposed
        |
        +---- Rust source of truth
                +---- Conversation pages
                +---- AgentRun events/checkpoints
                +---- PDF/reading state
                +---- English progress

React/WebView
  only keeps visible projections and active interaction resources
```

### 6.1 职责边界

- **Rust**：持久化完整业务状态、Agent Run、会话分页、诊断进程采样和真实数据快照。
- **React**：显示当前工作区、可视消息窗口和有限交互状态，不持有无限历史真相。
- **Resource Budget Manager**：统一决定可见资源、相邻预加载和缓存的预算，不允许各模块自行无限扩张。
- **Feature Runtime**：PDF、Mermaid、音频等声明创建、活跃、后台、销毁四类行为。
- **Diagnostics**：记录事实，不直接改变正常产品行为；强制 GC 和资源操作只存在于开发诊断构建。

### 6.2 生命周期状态

```text
created -> active -> background -> active
                    |            |
                    +-> disposed <-+
```

- `active`：允许交互和当前资源预算。
- `background`：停止预加载，释放不可见图形资源，只保留可恢复状态。
- `disposed`：销毁 Worker、Canvas、Object URL、音频和订阅。
- 恢复时从 Rust/持久化状态重新构建，不依赖被隐藏的旧组件。

## 七、统一资源预算与生命周期

### 7.1 Resource Registry

建立开发期可检查的资源注册表，每项运行资源至少记录：

- `owner`：工作区、会话、消息、PDF 文档或 Agent Run；
- `kind`：Canvas、Worker、Audio、ObjectURL、Timer、Observer、Cache；
- `estimatedBytes`；
- `createdAt/lastUsedAt`；
- `release()`；
- 是否可在后台立即释放。

注册表不是新的业务状态源，只用于统一释放和诊断。生产构建保留轻量预算逻辑，高级明细由编译期开关移除。

### 7.2 预算优先级

1. 当前用户交互资源；
2. 当前视口资源；
3. 当前视口相邻预加载；
4. 最近使用缓存；
5. 可重新从磁盘或 Rust 读取的数据。

达到软预算时从 5 向 1 驱逐。达到硬预算后仍不得驱逐未保存状态、活动 Agent 或当前可见内容。

### 7.3 无损内存压力响应

自动允许：

- 清空不可见 Canvas、SVG、highlight HTML 和附件预览；
- 停止 PDF/音频预取；
- 缩小相邻页面分辨率；
- 驱逐远离视口的消息页和 Workflow 详情；
- 终止空闲 Worker；
- 暂停后台动画、轮询和统计刷新。

自动禁止：

- 刷新主 WebView；
- 修改模型或权限；
- 中断正在运行的 Agent/审批；
- 删除原始 reasoning、历史消息或附件；
- 清理用户磁盘缓存而不告知。

## 八、PDF 内存重构

PDF 是 Plan07 中优先级最高的重型前端场景。

### 8.1 页面与缩略图虚拟化

当前实现会为 `pageCount` 中每一页创建 `PdfPage`，缩略图也为每一页创建组件。改为：

- 只挂载视口附近有限页窗口；
- 使用页面尺寸模型和占位高度维持滚动位置；
- 当前页变化时平滑替换窗口，不改变阅读位置；
- 缩略图列表使用虚拟化，仅创建可见项和少量 overscan；
- 页码导航可直接定位，不要求目标页组件预先存在。

### 8.2 Canvas 总预算

- 初始全局 PDF Canvas 预算：`64 MB`；
- 当前页优先使用适合当前 DPI 的清晰度；
- 相邻页采用 1x 或按剩余预算计算的比例；
- 单页不再只依赖 1200 万像素硬上限，还必须服从总预算；
- 离开视口后设置 `canvas.width = 0`、`height = 0` 并清理上下文引用；
- 不建立会长期保留位图的 Canvas 池；若使用池，必须以实际 backing store 字节计入预算。

### 8.3 渲染调度

- 同时运行的完整页面 RenderTask 初始上限为 1；
- 当前页可抢占相邻页低优先级任务；
- 快速滚动时取消已经离开窗口的 RenderTask；
- 文本层只为当前和真正可见页面生成；
- Annotation 层与文本层分开预算，隐藏时不保留大量 span。

### 8.4 PDF Worker 与文档生命周期

- 每个打开文档只有一个明确的 LoadHandle 所有者；
- 切换文档、关闭标签、离开 Work 和关闭窗口都必须等待或触发 `destroy()`；
- 搜索 generation、Range 请求和页面渲染共享取消令牌；
- `PDFPageProxy.cleanup()` 不再依赖“恰好不是当前页”的分支；
- 开发诊断记录 Worker 创建/销毁、PageProxy 数量和未完成 Range 请求。

### 8.5 搜索和缩略图

- 搜索移动到 Worker 或 Rust 流式任务，结果按页返回；
- 最多保留 100 个结果，但不保留全文文本；
- 新查询立即取消旧查询；
- 缩略图只保留可视窗口位图，使用 ImageBitmap 时必须调用 `close()`；
- 搜索、缩略图和主阅读渲染共享预算，不允许三套并行峰值。

### 8.6 PDF 验收

- 20、200、1000 页 PDF 均不按页数线性增加挂载 DOM；
- 10 次打开/关闭同一 PDF 后残留斜率 `<= 2 MB/次`；
- 200%/300% 缩放和 200% DPI 下不突破 Canvas 预算；
- 快速滚动、搜索和切换缩略图无白屏、错页、跳动或模糊长期不恢复。

## 九、Chat 与 Agent 内存重构

### 9.1 完整数据与活动窗口分离

现有 `Conversation[]` 不再作为完整历史常驻容器。目标结构：

```text
Conversation index       -> title/preview/count/current model
Message page store       -> Rust/disk, ordered pages
Agent Workflow store     -> Rust events/artifacts/checkpoints
Frontend message window  -> visible pages + small overscan
Active run projection    -> current status + latest bounded deltas
```

### 9.2 消息分页

- Rust 提供按游标/消息 ID 加载页面的命令；
- 默认页面大小从真实基线校准，建议从 30 条消息开始；
- 前端只保留当前视口、前后页和活动消息；
- 向上滚动时加载旧页，远离后可驱逐正文对象；
- 消息导航、引用跳转和搜索能够先定位再加载目标页；
- 当前发送上下文由 Rust 按需组装，不要求 Renderer 拥有完整会话。

### 9.3 reasoning 与 Workflow

- 原始 reasoning 和完整 Workflow 继续持久化；
- 折叠消息只加载摘要和计数；
- 用户展开时按 `agentRunId` 加载步骤页和必要 Artifact；
- 展开状态可以保留，但离开可视窗口后允许释放详细 DOM；
- 1000+ Workflow Event 不一次性投影和渲染；
- 活动 Run 使用有界增量缓冲，已持久化部分可从前端移除。

### 9.4 Rust Agent 所有权

- Rust `AgentRunManager` 持有运行状态、事件序号、预算和取消令牌；
- 页面切换后继续运行，React 重新订阅时按 sequence 补拉；
- React 不以本地 Promise 链决定 Run 是否存在；
- 保存采用增量事件或页面写入，避免每次流更新复制和序列化整个 Conversation；
- 等待审批时只保留轻量状态，审批内容从后端读取。

### 9.5 会话缓存修正

在分页迁移完成前，先修正现有缓存：

- 估算 reasoning、ActivatedSkill、ToolTrace、WorkflowSummary、Usage 和引用结构；
- Protected Conversation 仍受全局硬预算约束，超限时只保留运行所需窗口；
- 保存链不得捕获无限多旧 Conversation 快照；
- `conversationsRef` 和 React State 只共享引用，不创建深复制；
- 删除/清空会话时同步释放消息页、Workflow 投影和附件预览缓存。

### 9.6 Chat 验收

- 1000 条消息和 1000+ Workflow Event 的首屏不加载全部正文；
- 长对话内存随可视窗口稳定，不随历史总量线性增长；
- 滚动旧消息、展开 reasoning 和引用跳转无明显卡顿；
- 正在运行 Agent 时切换工作区，Run 不丢失且前端内存下降；
- 返回 Chat 后事件补拉无重复、乱序或 Workflow 状态倒退。

## 十、Markdown、Mermaid、代码高亮与 HTML 预览

### 10.1 Markdown 可见性

- 只对可见消息生成完整 Markdown DOM；
- outline、rehype/remark 派生结构按消息 memo，并在消息驱逐时释放；
- 流式尾部保持轻量解析，完成后再生成稳定结构；
- 大表格、长代码和数学公式必须有字符/节点预算。

### 10.2 Mermaid

- 保留当前按可见性加载和离场清空 SVG 的方向；
- 记录 Mermaid 首次加载增量、每图 SVG 字节和节点数；
- 限制单消息图表数量、单图字符和同时活跃图表数；
- 不可见图表只保留源码，不保留 SVG DOM；
- 若常规清理后首次使用 Mermaid 仍稳定残留超过约 30 MB，再评估 Worker/独立 WebView。

### 10.3 Highlight.js 与 KaTeX

- 语言模块继续按需加载；
- 不可见代码块释放高亮 HTML，保留源码；
- KaTeX 字体和 CSS 只在首次数学内容出现后加载；
- 记录首次加载模块增量，避免设置页或空白 Chat 提前加载。

### 10.4 HTML Preview

- Preview 文档状态必须设置数量和总字节上限；
- 预览窗口销毁时清理 Rust `HtmlPreviewState`；
- 大 HTML 不在主 Conversation 中重复保存完整字符串；
- 预览 WebView 是已有隔离边界，必须纳入进程树和销毁验收。

## 十一、附件、图片与音频

### 11.1 附件预览

当前 `read_chat_attachment_preview` 返回 Data URL，会产生原始文件、Base64、UTF-16 字符串和解码位图多份内存。目标方案：

- Rust 生成受控缩略图文件或返回可访问的 asset URL；
- 前端优先使用 `convertFileSrc`/asset protocol，不把大 Base64 常驻 JS Heap；
- 临时 Object URL 必须登记并 `revokeObjectURL()`；
- 缓存按解码后的估算像素字节，而不是只按字符串长度；
- 消息离开窗口或 Image Viewer 关闭后释放大图引用。

### 11.2 图片解码预算

- 同时可见图片设置总像素预算；
- 超大图片先使用缩略图，打开查看器后加载原图；
- Image Viewer 关闭后清空 `src` 和解码引用；
- 8 个附件上限继续保留，但不能假设 8 个附件天然安全。

### 11.3 English 音频

- Audio 元素保持单实例复用或严格替换；
- 每次播放前释放旧实例、事件和 URL；
- 切换单词、退出 Session、离开 English 和最小化时执行对应策略；
- 磁盘音频缓存上限不等同于内存缓存，不把预取文件读入常驻内存；
- Audio Service 约 9 MB 的基础成本单独记录，不把它误判为 Renderer 泄漏。

## 十二、工作区、设置页与后台休眠

### 12.1 工作区挂载

- 保留单 Workspace Host；
- 为每个视图增加明确的 `onActive/onBackground/onDispose` 合同；
- 禁止通过 CSS `display:none` 长期隐藏重型工作区；
- App 顶层只保留真正全局的轻量服务，重型数据在目标视图出现时加载。

### 12.2 设置页代码拆分

- SettingsPage 仅保留导航外壳；
- General、Models、Usage、Debug、About 等面板按分类动态加载；
- 离开分类后卸载包含大列表、统计或调试数据的面板；
- Memory Diagnostics 面板只在开发诊断构建注册。

### 12.3 最小化

窗口最小化且无前台交互 60 秒后：

- 停止非必要动画和页面预加载；
- 清理不可见 Canvas、SVG 和大图片；
- 暂停统计轮询与非必要刷新；
- 保持活动 Agent、审批和必要音频任务；
- 恢复窗口时先显示稳定外壳，再按优先级恢复内容。

### 12.4 关闭与托盘

- 关闭主窗口继续销毁 WebView2；
- 关闭前完成必要的状态保存和资源清理；
- 按当前已确认策略取消未完成 Run、审批、附件任务和其他不可见任务；
- 该规则覆盖 Plan06 中与“关闭主窗口继续运行”冲突的旧描述，后续实现和文档必须统一。

## 十三、开发内存诊断功能

### 13.1 编译期开关

建议同时设置：

- Rust Cargo feature：`memory-diagnostics`；
- Frontend build flag：`VITE_MEMORY_DIAGNOSTICS=true`；
- 正式构建脚本明确验证两者均关闭。

正式版不包含：

- 真实数据快照基准；
- 调试端口和 CDP 自动化入口；
- 强制 GC、强制销毁资源按钮；
- 详细文件、会话和对象枚举；
- 高级采样时间线。

### 13.2 设置页调试入口

在现有“调试”分类增加内存区域：

- 当前场景与场景进入时间；
- Mnemora/WebView2 进程树分项；
- JS Heap、DOM、Canvas、Worker、Audio 和缓存摘要；
- 最近 5/15/30/60 秒采样；
- 开始/停止场景基准；
- 创建真实数据只读快照；
- 导出脱敏 JSON；
- 开发专用的资源释放验证操作。

默认采样频率应低，打开详细时间线后才提高频率，避免监控本身造成显著开销。

### 13.3 真实数据只读快照

- Conversation、Settings、Learning SQLite、Library SQLite 等可写数据复制到临时目录；
- SQLite 使用一致性备份，不在数据库写入过程中直接复制不完整文件；
- 大型 PDF 和只读附件可引用原路径，但测试层只以只读方式打开；
- 快照不包含 API Key、Authorization、Cookie、密码或系统凭据；
- 基准结束后删除临时快照，删除范围必须验证在专用临时目录内。

### 13.4 诊断导出

默认只导出：

- 字节数、计数、时间、场景 ID、版本和硬件信息；
- 不导出消息正文、reasoning、工具输入输出、PDF 文本和附件内容；
- 路径只保留类别或哈希，不保留用户目录明文；
- 所有数据留在本机，由开发者主动选择文件位置。

## 十四、由数据触发的隔离策略

### 14.1 触发条件

只有同时满足以下条件才进入隔离评审：

1. Release 场景基线可重复；
2. 常规生命周期、缓存和虚拟化已经完成；
3. 目标功能离场 60 秒后稳定残留约 `30 MB` 以上；
4. 至少 3 轮、10 次进入/退出复现；
5. Heap/DOM/Canvas/模块加载证据能够指向具体引擎；
6. 隔离方案预估净收益大于自身基础成本，并通过性能门禁。

### 14.2 Worker 适用范围

优先用于纯计算或可结构化输入输出的任务：

- PDF 文本搜索和解析；
- 大型转换、索引或排序；
- 可使用 OffscreenCanvas 的有限渲染任务。

Worker 必须支持取消、超时、终止和有界消息大小。终止 Worker 后不得由主线程缓存再次持有全部结果。

### 14.3 独立 WebView 适用范围

仅用于强依赖 DOM/Canvas、且主 Renderer 无法充分回收的第三方运行时。它可以嵌入主窗口，不应弹出或闪烁。

生命周期：

```text
进入功能 -> 创建临时 WebView -> 传入有限状态 -> 执行/显示
离开功能 -> 保存业务状态 -> 断开 IPC -> 销毁 WebView -> 验证 Renderer 退出
```

不得为了理论上的隔离同时常驻多个隐藏 WebView，否则会增加 Browser/Renderer 基础成本。

- 最小化恢复无闪烁、焦点抢夺或输入失效；
- 关闭到托盘后 WebView2 进程退出；
- 所有设置、笔记、阅读和学习数据保持正确。

## 十八、最终验收标准

### 18.1 内存

- Release 场景达到首轮 `220/280/380 MB` 临时门槛，或经用户确认采用有完整证据的新口径。
- PDF/English 离场 60 秒回到场景基线 `+30 MB` 内。
- 10 次往返残留斜率 `<=2 MB/次`。
- 1000 消息/事件不使 Renderer 随总历史线性增长。
- 关闭主窗口后 WebView2 进程组退出，只保留预期 Rust/托盘成本。

### 18.2 流畅性

- 达到第五章性能门禁。
- 内存清理不产生持续主线程长任务。
- PDF 当前页清晰度、滚动和缩放体验不低于基线。
- Chat 输入、滚动和流式输出不因分页和驱逐卡顿。
- 重型视图恢复先显示稳定外壳，不出现整窗闪烁。

### 18.3 正确性

- 不丢失消息、reasoning、Workflow、批注、阅读状态或学习进度。
- 不重复 Agent 事件和工具副作用。
- 缓存驱逐只影响重建成本，不改变业务结果。
- 真实数据测试不修改源数据。
- 正式构建不包含高级诊断和真实数据入口。

### 18.4 可持续性

- CI 能检测预算回归。
- 每个重型资源都有所有者和释放路径。
- 新增 Canvas、Worker、Audio、Object URL 或全局缓存必须声明预算。
- 提高预算必须附带报告并经明确审查，不能只修改数字让 CI 通过。
- 首轮门槛达成后继续评估 Stretch A/B。

## 十九、风险与回滚

### 风险 1：过度驱逐造成资源抖动

对策：使用软/硬预算、迟滞区间和最近使用时间；当前页和当前消息始终最高优先级。若同一资源短时间反复创建，降低驱逐频率而不是放弃总预算。

### 风险 2：PDF 降分辨率影响阅读

对策：只降低相邻页，当前页在预算内优先清晰；显示页进入稳定视口后自动提升，不永久保存低质量位图。

### 风险 3：分页导致跳动或历史缺失

对策：稳定消息 ID、虚拟高度锚点和页面校验；Rust 完整数据源始终保留，前端驱逐不得删除持久化数据。

### 风险 4：Agent 后端化产生状态分叉

对策：Rust Event Store 是唯一真相；React 只按 sequence 投影，禁止前端自行推进 Run 状态。

### 风险 5：诊断本身增加内存

对策：默认低频采样、环形缓冲、脱敏小报告；高级对象枚举仅在面板打开和显式操作时运行。

### 风险 6：真实数据快照不一致

对策：SQLite 一致性备份、只读打开、专用临时目录和结束清理；任何快照错误都不得回写源目录。

### 风险 7：独立 WebView 基础成本高于收益

对策：先做小型验证并比较净收益；未通过 30 MB 残留门槛或双门禁时不实施。

### 风险 8：WebView2 版本改变基线

对策：报告记录 Runtime 版本；升级后运行全套基线，区分产品回归与 Runtime 变化，但产品预算不能自动放宽。

### 回滚策略

- P07.0 诊断基础设施可独立保留，不影响产品路径。
- P07.1 每类资源治理独立提交，可按模块回滚。
- P07.2 PDF 虚拟化保留开发 feature flag，直到滚动和定位测试稳定。
- P07.3 消息分页迁移期间旧 Conversation JSON 只读兼容，不覆盖原文件。
- P07.4 Agent 投影切换保留事件重放校验，禁止两套状态同时写入。
- P07.7 隔离以模块级开关灰度，仅用于开发验证，不暴露为用户模式。
- 回滚不能通过重新提高预算掩盖功能回归。
