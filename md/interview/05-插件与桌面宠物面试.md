# 插件体系与桌面宠物模拟面试（Grilling 版）

> 建议时长：30–35 分钟。  
> 目标：能区分 Skill、Plugin、Tool、MCP、宿主插件和桌面宠物资源，并回答供应链、权限、窗口、资源和跨平台问题。

## 1. 为什么要插件？

**问：插件解决的核心问题是什么？**

**推荐答：**  
插件提供可发现、可安装、可授权、可更新和可回滚的扩展边界。它不是“让第三方代码随便执行”，而是把能力声明、宿主贡献点、权限和生命周期标准化。

**追问：为什么不继续增加内置 Skill？**

**答：**  
Skill 适合方法论，不能覆盖主题、Reader、Pet Pack、命令和未来工具。插件可以组合这些能力，但必须继续受 Mnemora 的来源、权限、内存和恢复合同约束。

## 2. GitHub 参考如何取舍？

**问：你从 Codex、Claude Code、VS Code、Obsidian、Raycast 学到什么？**

**答：**  
Codex 展示 Manifest、插件包校验、安装审批和宠物资源生命周期；Claude Code 展示 plugin.json、commands/agents/skills/hooks/MCP 分层和官方插件目录；VS Code 展示 Contribution Points/Activation Events；Obsidian 展示版本和设置；Raycast 展示 Marketplace 审核和发布规范。不能直接复制它们的权限模型。

**追问：Claude Code 有官方桌面宠物吗？**

**答：**  
当前官方仓库展示的是插件、Skill、Hook 和 Agent，没有官方桌面宠物实现。社区宠物只能作为非官方交互参考，不能写成官方设计。

## 3. Manifest 与贡献点

**问：Manifest 至少要声明什么？**

**答：**  
schemaVersion、稳定 id、版本、发布者、许可证、仓库、来源 Commit、最小 Mnemora 版本、平台、组件、贡献点、权限、激活事件、内容 Hash 和运行预算。

**追问：为什么 Manifest 不能直接授予权限？**

**答：**  
Manifest 是声明，Permission Broker 才是用户授权和宿主执行边界。否则安装包可以自报拥有文件、网络和 Shell 权限。

**问：Contribution Point 是什么？**

**答：**  
是宿主允许插件挂接的固定扩展点，例如 skills、documentReaders、petPacks、commands、noteToolbar、taskObservers。未知扩展点必须拒绝或降级。

## 4. 供应链与回滚

**问：如何防恶意插件和更新劫持？**

**答：**  
来源白名单/审核、许可证、固定 Commit、内容 Hash、签名（后续）、staging 解压、路径/大小/文件类型校验、权限预览、健康检查、旧版本保留和自动回滚。更新扩大权限时必须重新确认。

**追问：压缩包有什么风险？**

**答：**  
路径穿越、符号链接、解压炸弹、超大单文件、过深目录和恶意资源。必须限制压缩大小、解压总量、文件数、深度和归档类型，并在临时目录原子安装。

**问：插件崩溃会不会拖垮主进程？**

**答：**  
声明式资源不执行代码；需要执行时用 Worker/WASM/受控 Sidecar，设置超时、取消、内存和输出上限。主进程不把 AppHandle、SQLite 连接或任意 IPC 直接交给插件。

## 5. Skill、Tool、MCP、Plugin 的边界

**问：四者如何区分？**

**答：**

- Skill：方法论和提示正文；
- Tool：有 Schema 的一次结构化动作；
- MCP：工具/资源协议和服务器连接方式；
- Plugin：可包含 Skill、Tool、Reader、命令、主题或 Pet Pack 的可安装分发单元。

插件不应自动继承普通 Chat 的全部 Tool；每个贡献点都要重新声明权限、风险和资源成本。

## 6. 桌面宠物的产品价值

**问：宠物为什么不是噱头？**

**答：**  
它是低打扰的任务和学习状态投影：用户无需切回窗口就知道任务在思考、等待确认、完成或失败。但它不是第二个 Chat，也不应默认监控屏幕、麦克风或其他窗口。

**追问：为什么要独立窗口？**

**答：**  
透明、置顶、点击穿透、拖动、多屏定位和独立销毁更容易隔离；主窗口关闭时可以明确销毁宠物窗口和订阅，不把资源生命周期混在 React 页面里。

## 7. 状态和隐私

**问：宠物如何映射 Agent 状态？**

**答：**  
用有限状态机 Hidden、Idle、Thinking、Tooling、Waiting、Success、Error、Sleeping。事件只传 eventType、taskId、phase、progressBucket、severity 和时间，不传完整消息、附件路径或请求体。

**追问：用户不想被打扰怎么办？**

**答：**  
默认关闭、无声音、quiet hours、全屏暂停、Reduced Motion、点击穿透、托盘隐藏和事件类别开关。重要的是可预测和可撤销，而不是增加更多动画。

## 8. Pet Pack 资源合同

**问：第三方宠物素材如何接入？**

**答：**  
声明式 Pet Pack 包含 manifest、sprites/frames、animations、preview、LICENSE、NOTICE 和 content hash；限制帧数、像素面积、FPS、解码字节和总资源量。优先 SVG/CSS/PNG/WebP，不允许动画脚本。

**追问：Codex 宠物有哪些值得借鉴的细节？**

**答：**  
Catalog、asset pack、固定版本缓存、结构校验、Picker、自定义宠物、动画帧时长、状态通知生命周期和 Reduced Motion。要注意 Codex 的实现是终端 TUI，不是跨平台透明桌面窗口。

## 9. 跨平台窗口和内存

**问：Windows/macOS/Linux 最大坑是什么？**

**答：**  
透明窗口、点击穿透、置顶、DPI、多显示器坐标、任务栏/全屏行为和窗口销毁语义不同。位置要保存逻辑坐标和显示器标识，显示器消失时回退；所有平台都要有 smoke test。

**追问：宠物会不会导致常驻内存上涨？**

**答：**  
资源进入 ResourceRegistry；隐藏/静默时停止帧调度，长时间空闲使用静态帧，切换资源包释放旧纹理，关闭主窗口销毁窗口和订阅。宠物必须进入内存 Benchmark。

## 10. 终极白板题

**题目：设计一个“文献阅读宠物”插件，能在用户读 PDF 时提示长时间阅读，任务完成时庆祝，并允许社区上传素材。**

**推荐答：**

1. Manifest 只声明 petPack、taskObserver 和 settings；
2. taskObserver 只收脱敏的 PDF open、page change、annotation saved、task done 事件；
3. 需要阅读时长使用本地计时，不捕获屏幕；
4. Pet Pack 经过许可证、Hash、图片尺寸、帧数和安全资源校验；
5. 默认无声音、支持 quiet hours、Reduced Motion 和关闭；
6. 事件和资源均有 owner、引用计数、预算和销毁路径；
7. Marketplace 更新使用 staging、健康检查、旧版本回滚；
8. 社区上传不能带脚本、外链或任意网络请求；
9. 用户可查看插件权限、来源、版本和数据范围；
10. Benchmark 覆盖安装、切换、隐藏、长时间运行和窗口销毁。

## 11. 红线和最终取舍

红线：

- 动态加载未知 DLL/EXE；
- 把安装等同于授权；
- 默认录屏或监听麦克风；
- 社区素材无许可证和 Hash；
- 宠物状态携带原文或敏感路径；
- 没有回滚和资源释放。

如果只能先做一个插件能力，先做声明式 Skill/Theme/Pet Pack + Manifest/Permission/Resource 合同；执行型 Tool 和 Marketplace 放在审计、沙箱和回滚之后。
